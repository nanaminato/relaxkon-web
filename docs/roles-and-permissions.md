# 角色与功能权限

角色使用稳定的 `code` 参与授权，`name` 用于显示，`description` 用于说明用途。修改显示名称不改变账户权限或功能策略。角色编码创建后不再修改。

`admin`、`user`、`vip` 是系统角色，不能删除。系统角色可以修改显示名称和说明。普通角色用于组合不同功能和限额，不会仅因创建角色而获得后台管理权限。

同一账户可以绑定多个角色。功能权限采用合并授权：至少一个角色开启该功能时允许使用；每分钟、每天和并发限额分别取已开启角色中的最大值，其中空值表示无限制。未开启角色的限额不参与合并。

管理角色时，先通过成员数量和关联账户检查影响，再调整功能策略。功能策略保存使用版本校验；发生冲突时重新加载并核对其他管理员的更改。删除自定义角色会移除该角色的账户关联。最后一个管理员的管理资格必须保留。

后台入口通过服务端实时身份接口判断管理资格，所有管理 API 仍独立检查管理员权限。账户角色变更后，现有会话会失效，需要重新登录。

已有数据库先停止应用写入，执行后端 `src/Turbo.Auth/Resources/merge/role-system-upgrade.sql`，再启动新版后端。具体步骤参见后端 `docs/roles-and-permissions.md`；本次未对业务库应用结构升级。升级前应核对现有角色名称，因为旧名称将成为稳定编码，以保留已有功能策略的关联。
